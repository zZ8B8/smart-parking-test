# 测试计划 · 智能停车管理系统接口

## 1. 测试目标

验证停车场后端核心业务链路的正确性与健壮性，重点覆盖：

1. 车位资源管理（总数、空闲/占用、按类型分配）
2. 车辆入场的车牌校验、车位分配、容量耗尽处理
3. **计费规则的正确性与边界**（免费时长、首小时、按小时累加、单日封顶）
4. 出场结算与车位释放
5. 月卡免费规则（含有效期）
6. 高并发入场时的车位分配正确性（是否一车位多车）
7. 重复出场等操作的数据一致性

## 2. 测试范围

| 范围内 | 范围外 |
|---|---|
| 全部 9 个 HTTP 接口的功能与异常分支 | 道闸/地磁/摄像头等硬件对接 |
| 计费规则的全部分支与边界 | 支付通道对接 |
| 车位分配的容量边界与并发 | 前端页面 UI |
| 月卡有效期判定 | 数据库层实现（当前为内存存储） |
| 停车记录的状态与数据一致性 | 性能压测、长时间稳定性 |

## 3. 测试策略

| 层次 | 内容 | 对应用例 |
|---|---|---|
| L1 冒烟 | 车位总览 → 入场 → 出场计费 → 再查总览 | `tools/smoke_check.py` |
| L2 功能 | 各接口正常路径 + 参数校验 + 边界值 | `tests/test_*.py` 共 50 条 |
| L3 专项 | 计费取整、幂等性、并发、时效性 | `tests/bugs/` 共 11 条 |

### 用例设计方法

- **等价类划分**：车牌格式、日期格式、车位状态/类型筛选
- **边界值分析**：15 分钟免费边界、恰好 1/2/3 小时、24 小时封顶、车位恰好停满
- **状态迁移法**：车辆「在场 → 出场」；重复出场
- **容量边界**：7 个车位、1 个充电位
- **并发测试**：`threading.Barrier` 同步多线程入场
- **反向用例**：月卡「有效期内免费」对应的「过期应收费」

### 时间处理

「停车 150 分钟」如果真实等待无法接受。项目在被测系统内提供
`service.advance_clock(seconds)`，把时钟整体前移 —— 用例在毫秒内完成，
且**不修改操作系统时间**、不影响其他进程。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 并发缺陷偶发不可复现 | 测试结论不稳定 | 被测系统显式模拟持久层延迟（`DB_ROUND_TRIP`），放大竞态窗口；并用 `Barrier` 让线程精确对齐 |
| 并发用例中成功车辆数浮动 | 断言不稳定 | 断言「所有成功车辆占用同一车位」这一**稳定现象**，而非固定数量 |
| 计时用例受真实耗时影响 | 边界值判定偏移 | 时钟偏移量按整秒给，取整后落在预期边界上 |
| 内存存储，用例间数据污染 | 结果互相干扰 | `autouse` fixture 在每个用例前重置数据与时钟 |
| 路径含中文车牌被 URL 编码 | 路由匹配失败 | 服务端匹配前先 `unquote` 解码 |
