## 1. 测试目的

对智能停车管理系统 V1.0 的主流程（入场 → 分配车位 → 出场结算 → 释放车位）
以及月卡业务进行系统测试，验证功能是否满足《需求规格说明书》，
并在过程中发现缺陷、评估质量、给出上线建议。

本项目的特殊之处：产品**刻意内置了 4 个缺陷**（计费取整、出场幂等、
并发超卖、月卡有效期）。测试的目的除了「验证功能」，还包括
「证明这些缺陷确实能被测试手段发现」，因此**缺陷发现率是核心质量指标之一**。

## 3. 测试策略

| 测试类型 | 方法 | 工具 |
| --- | --- | --- |
| 功能测试 | 等价类划分、边界值分析、判定表、场景法 | 浏览器、Postman |
| 接口测试 | 直接调接口，验证参数与响应 | Postman / Apifox / pytest |
| 数据校验 | 反向查库，比对车位状态与流水 | Navicat、SQL |
| 并发测试 | 多线程同时入场，验证不超卖 | pytest + threading |
| 状态机测试 | 对同一记录重复触发状态流转 | Postman |
| 业务规则测试 | 有效期边界（有效 / 过期月卡） | Postman、测试时钟 |
| 抓包分析 | 观察请求参数与响应 | Fiddler |
| 回归测试 | 缺陷修复后重跑用例 | pytest |

### 3.1 测试设计方法示例

**边界值分析**（计费小时数）：

| 点 | 停车时长 | 正确小时数 | 应收 |
| --- | --- | --- | --- |
| 免费上边界 | 15 分钟 | 0 | ¥0 |
| 免费上边界外 | 16 分钟 | 1 | ¥5 |
| 首小时边界 | 60 分钟 | 1 | ¥5 |
| 首小时边界外 | 61 分钟 | **2** | **¥8** |
| 整小时 | 120 分钟 | 2 | ¥8 |
| 封顶 | 13 小时 | 13 | ¥40 |

**等价类划分**（车牌）：

| 类 | 数据 | 预期 |
| --- | --- | --- |
| 有效·标准 | 京A12345 | 通过 |
| 有效·新能源 | 粤B8888E | 通过 |
| 无效·空 | `""` | 400 INVALID_PLATE |
| 无效·第二位非字母 | 京12345 | 400 |
| 无效·长度不足 | 京A123 | 400 |
| 无效·长度超限 | 京A12345678 | 400 |
| 无效·无省份简称 | ABC12345 | 400 |
| 无效·含特殊字符 | 京A-1234 | 400 |

**状态机测试**（停车记录）：

| 起始状态 | 事件 | 预期 |
| --- | --- | --- |
| PARKING | 出场 | CLOSED，释放车位 |
| CLOSED | 出场 | 400，不得再释放车位 |

## 6. 准入与准出标准

### 6.1 测试准入

1. 数据库可正常初始化，服务能启动并返回 `/health` 为 UP。
2. 前端 5 个页面均可正常打开，静态资源加载无 404。
3. 车位网格图能正确渲染 7 个车位并按状态着色。
4. 测试时钟接口可用，能模拟「停车 N 小时」。
5. 接口文档（02）与实现一致。

### 6.2 测试准出

| 指标 | 标准 |
| --- | --- |
| 用例执行率 | 100% |
| 用例通过率 | ≥ 95%（不含刻意缺陷对应的预期失败） |
| 严重缺陷 | 全部已提交、已复现、有明确复现步骤 |
| 数据一致性 | 正常业务流程下三条不变量全部成立 |
| 文档 | 用例、缺陷报告、测试报告齐全 |

> **本靶场的特殊约定**：4 个内置缺陷在 V1.0 中**不会被修复**，
> 它们以 `xfail(strict=True)` 固化在回归套件里。准出结论应为
> **「不通过 / 有条件通过」**，并在报告中明确列出风险。

## 7. 缺陷分级标准

| 等级 | 定义 | 示例 |
| --- | --- | --- |
| 严重 | 数据错乱、资损、大范围不可用 | BUG-S3 车位超卖 |
| 高 | 主流程逻辑错误、状态机错误、持续漏收 | BUG-S2、BUG-S4 |
| 中 | 非主流程功能错误、金额小偏差 | BUG-S1 |
| 低 | 文案、样式、体验问题 | — |

| 优先级 | 定义 |
| --- | --- |
| P0 | 必须立即修复 |
| P1 | 本迭代内修复 |
| P2 | 可延后 |
| P3 | 建议修复 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 计费依赖真实时间，测试无法等待数小时 | 计费用例不可执行 | 提供测试时钟接口，秒级模拟数小时 |
| 并发缺陷偶现，难稳定复现 | 回归不可信 | 用 `SIMULATE_DB_LATENCY` 放大竞态窗口 |
| 数据库连接建立慢（~0.27s） | 并发请求被串行化 | 使用连接池 + 启动预热 |
| 时间精度导致计费边界偶发失败 | 用例不稳定 | 用例避开整点边界，另设专项边界用例 |
| 数据被多窗口并发修改 | 结果不可信 | 每条用例前自动重置数据与时钟 |
| 缺陷修复后旧用例失效 | 回归假绿 | 用 `xfail(strict=True)`，修复即报 XPASS |
