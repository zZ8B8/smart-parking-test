## 1. 项目背景与目标

智能停车管理系统覆盖「车辆入场 → 自动分配车位 → 计时 → 出场结算 → 释放车位」
这条完整业务链，并提供月卡管理。

系统的**真实目的是作为测试练习靶场**：除正常功能外，刻意包含 4 个典型缺陷
（计费取整、幂等性、并发、业务规则有效期），供测试人员通过黑盒、自动化、
数据校验等手段发现。

业务目标：

1. 提供一条可运行的停车管理主流程，供功能测试、接口测试、并发测试使用。
2. 提供真实数据库（MySQL），供 SQL 校验、数据一致性反向验证使用。
3. 内置可复现的缺陷，供缺陷管理流程（提交、复现、回归）练习。

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| 车主 | 驾车进出车场 | 入场、出场 |

## 3. 功能需求

需求编号规则：`REQ-模块-序号`。优先级：高 / 中 / 低。

### 3.1 车位模块

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| REQ-SPOT-001 | 车场固定 7 个车位：普通 4 个、无障碍 2 个、充电 1 个 | 高 |
| REQ-SPOT-002 | 可查看车场总览：车位总数、空闲数、占用数、占用率 | 高 |
| REQ-SPOT-003 | 总览按车位类型给出明细统计 | 中 |
| REQ-SPOT-004 | 可查询车位列表，支持按状态与类型筛选 | 高 |
| REQ-SPOT-005 | 车位应展示编号、类型、状态、当前占用车牌 | 中 |
| REQ-SPOT-006 | 占用车位时记录车牌，释放后车牌清空 | 高 |

### 3.2 入场模块

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| REQ-ENTRY-001 | 输入车牌，系统自动分配第一个空闲车位 | 高 |
| REQ-ENTRY-002 | 可指定车位类型入场（普通 / 无障碍 / 充电） | 中 |
| REQ-ENTRY-003 | 车牌格式校验：省份简称 + 字母 + 5~6 位字母数字 | 高 |
| REQ-ENTRY-004 | 同一车牌在场时不可重复入场，返回 409 | 高 |
| REQ-ENTRY-005 | 无可用车位时拒绝入场，返回 409 | 高 |
| REQ-ENTRY-006 | 指定类型无空位时，即使其他类型有空位也应拒绝 | 中 |
| REQ-ENTRY-007 | 入场成功生成停车记录，状态为「在场」 | 高 |
| REQ-ENTRY-008 | 入场成功写入一条 ENTRY 车位流水 | 中 |
| REQ-ENTRY-009 | **同一车位在同一时刻只能分配给一辆车（并发安全）** | 高 |

### 3.3 出场与计费模块

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| REQ-EXIT-001 | 出场结算费用并释放车位 | 高 |
| REQ-EXIT-002 | 计费：≤15 分钟免费 | 高 |
| REQ-EXIT-003 | 计费：首小时 5 元（**不足 1 小时按 1 小时**） | 高 |
| REQ-EXIT-004 | 计费：此后每满 1 小时 3 元（**不足 1 小时按 1 小时**） | 高 |
| REQ-EXIT-005 | 计费：单次封顶 40 元 | 中 |
| REQ-EXIT-006 | 出场后记录状态变为「已出场」，并记录出场时间与时长 | 高 |
| REQ-EXIT-007 | 出场后车位恢复空闲，可被其他车辆使用 | 高 |
| REQ-EXIT-008 | 出场写入一条 EXIT 车位流水 | 中 |
| REQ-EXIT-009 | 未入场的车牌出场应返回 404 | 中 |
| REQ-EXIT-010 | **出场必须幂等**：同一记录重复出场应被拒绝，不得重复释放车位 | 高 |
| REQ-EXIT-011 | **释放车位不得影响已停入该车位的其他车辆** | 高 |

### 3.4 月卡模块

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| REQ-CARD-001 | 可为车牌办理月卡，指定有效期（YYYY-MM-DD） | 高 |
| REQ-CARD-002 | 同一车牌重复办理应更新原卡，不新增 | 中 |
| REQ-CARD-003 | 可查询单车牌月卡信息 | 高 |
| REQ-CARD-004 | 月卡信息应标识是否已过期 | 中 |
| REQ-CARD-005 | **持有有效期内月卡的车牌出场免费** | 高 |
| REQ-CARD-006 | **过期月卡不再享受免费，应按普通车辆计费** | 高 |
| REQ-CARD-007 | 有效期格式非法应返回 400 | 中 |

### 3.5 数据一致性需求

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| REQ-DATA-001 | 占用车位数必须等于「在场」状态的停车记录数 | 高 |
| REQ-DATA-002 | 每个占用车位必须对应一条在场记录，且车牌一致 | 高 |
| REQ-DATA-003 | 对每个车位：ENTRY 流水数 − EXIT 流水数 = 1（占用）/ 0（空闲） | 高 |
| REQ-DATA-004 | 系统应提供数据一致性自检能力 | 中 |

> **加粗的 5 条需求（REQ-ENTRY-009、REQ-EXIT-010、REQ-EXIT-011、REQ-CARD-006、
> REQ-EXIT-003/004 的取整要求）在本版本中未被正确实现**，对应 4 个缺陷，
> 见 `05-缺陷报告.md`。

## 5. 数据字典

数据库名 `smart_parking`，字符集 `utf8mb4`，引擎 `InnoDB`。

### 5.1 spots（车位表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INT | PK, AUTO_INCREMENT | 车位 ID |
| code | VARCHAR(16) | UNIQUE, NOT NULL | 车位编号，如 A-001 |
| type | VARCHAR(20) | NOT NULL | NORMAL / ACCESSIBLE / CHARGING |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'FREE' | FREE / OCCUPIED |
| plate | VARCHAR(20) | NULL | 当前占用车牌，空闲为 NULL |

### 5.2 tickets（停车记录表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INT | PK, AUTO_INCREMENT | 记录 ID |
| plate | VARCHAR(20) | NOT NULL, INDEX | 车牌 |
| spot_id | INT | FK → spots.id | 分配的车位 |
| entered_at | DATETIME | NOT NULL | 入场时间 |
| exited_at | DATETIME | NULL | 出场时间 |
| duration_minutes | INT | NULL | 停车时长（分钟） |
| fee | DECIMAL(10,2) | NULL | 停车费 |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'PARKING' | PARKING / CLOSED |

### 5.3 month_cards（月卡表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| plate | VARCHAR(20) | PK | 车牌 |
| valid_until | DATE | NOT NULL | 有效期至 |
| issued_at | DATETIME | NOT NULL | 办理时间 |

### 5.4 spot_logs（车位流水表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INT | PK, AUTO_INCREMENT | 流水 ID |
| spot_id | INT | FK → spots.id | 车位 |
| action | VARCHAR(20) | NOT NULL | ENTRY / EXIT |
| plate | VARCHAR(20) | NOT NULL | 车牌 |
| ticket_id | INT | NULL | 关联停车记录 |
| created_at | DATETIME | NOT NULL | 发生时间 |

> **数据一致性反向校验公式**（发现 BUG-S2、BUG-S3 的关键手段）：
>
> ```sql
> -- 1. 占用车位数 = 在场记录数
> SELECT (SELECT COUNT(*) FROM spots WHERE status='OCCUPIED') AS occupied,
>        (SELECT COUNT(*) FROM tickets WHERE status='PARKING') AS parking;
>
> -- 2. 每个占用车位都有对应在场记录
> SELECT s.code, s.plate FROM spots s
> WHERE s.status='OCCUPIED'
>   AND NOT EXISTS (SELECT 1 FROM tickets t
>                   WHERE t.spot_id=s.id AND t.status='PARKING');
>
> -- 3. 车位流水收支平衡
> SELECT s.code, s.status,
>   (SELECT COUNT(*) FROM spot_logs l WHERE l.spot_id=s.id AND l.action='ENTRY') AS en,
>   (SELECT COUNT(*) FROM spot_logs l WHERE l.spot_id=s.id AND l.action='EXIT')  AS ex
> FROM spots s;
> -- en - ex 应等于 1（OCCUPIED）/ 0（FREE）
> ```

## 7. 状态机

### 7.1 停车记录状态

```
                 ┌──────────────┐
   入场成功 ────▶ │  PARKING     │  在场
                 │  在场         │
                 └──────┬───────┘
              出场结算   │
                        ▼
                 ┌──────────────┐
                 │  CLOSED      │  已出场
                 └──────────────┘
                        │
                        │ 再次调用出场
                        ▼
                  ❌ 应拒绝（400）
                  实际被放行 ── BUG-S2
```

| 起始状态 | 事件 | 应有结果 | 本版本实际结果 |
| --- | --- | --- | --- |
| PARKING | 出场 | → CLOSED，释放车位 | ✅ 正确 |
| CLOSED | 出场 | ❌ 拒绝（400） | ❌ 放行，重复释放车位，**BUG-S2** |

### 7.2 车位状态

```
   FREE ──── 车辆入场 ───▶ OCCUPIED（记录 plate）
     ▲                         │
     └──── 车辆出场 ───────────┘

   ⚠️ 重复出场会把 OCCUPIED 直接改成 FREE，
      即使此刻车位里停着的是**另一辆车** —— BUG-S2
```
