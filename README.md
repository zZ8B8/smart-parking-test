# 智能停车管理系统 · 接口自动化测试实践

一个 **停车场业务后端**的接口测试实践项目：被测系统（SUT）+ pytest 自动化测试套件 + 完整测试文档。

覆盖停车场的核心业务：**车位管理 → 车辆入场 → 停车计费 → 出场结算 → 月卡免停**，
其中计费规则与并发入场是两个最容易出错的地方，本项目重点攻击这两处。

> 说明：这是一个**个人测试实践项目**。被测系统由本人按真实停车场业务规则实现，
> 缺陷是刻意保留的真实编码疏漏（不做任何标记），供测试用例去发现。

## 2. 快速运行

被测系统**零第三方依赖**，Python 3.8+ 直接跑：

```bash
# 启动服务（默认 127.0.0.1:5002）
python sut/server.py

# 另开一个终端做冒烟检查
python tools/smoke_check.py
```

跑自动化测试需要 pytest：

```bash
pip install -r requirements.txt

# 全量测试
pytest

# 只看缺陷复现
pytest tests/bugs -v

# 看每个缺陷的实际观测值
python tools/collect_evidence.py
```

Windows 用户可直接双击 `一键运行测试.bat` ——
脚本会**自己探测**机器上可用的 Python 解释器（不依赖 PATH 里的 `python`，
因为 Windows 上它常常是微软商店的占位符），缺 pytest 会自动安装，然后直接跑测试。

## 3. 业务规则

### 计费

| 条件 | 费用 |
|---|---|
| 停车 ≤ 15 分钟 | 免费 |
| 超过 15 分钟 | 首小时 5 元（不足 1 小时按 1 小时） |
| 之后 | 每满 1 小时 3 元（不足 1 小时按 1 小时） |
| 单日上限 | 封顶 40 元 |

### 车位

- 共 7 个车位：4 个普通（A 区）、2 个无障碍（B 区）、**1 个充电（C 区）**
- 入场自动分配一个空闲车位；可指定车位类型
- 车位耗尽时拒绝入场（HTTP 409）

### 月卡

- 按车牌绑定，有效期内免费出场

## 5. 发现并定位的缺陷

| 编号 | 标题 | 级别 | 类型 | 根因 |
|---|---|---|---|---|
| BUG-S1 | 计费时长向下取整，超时零头被抹掉（少收费） | 高 | 业务规则 | `calc_fee` 用 `//` 取整，应按「不足 1 小时按 1 小时」向上取整 |
| BUG-S2 | 重复出场会释放他人正在使用的车位 | 严重 | 幂等性 | `exit_vehicle` 取「最后一条记录」结算，未校验是否已出场 |
| BUG-S3 | 并发入场导致一个车位发给多辆车 | 严重 | 并发 | `entry` 中「查车位」与「占车位」非原子，无锁保护 |
| BUG-S4 | 过期月卡依然免费出场 | 高 | 业务规则 | `_has_free_pass` 只判断月卡是否存在，未比对有效期 |

缺陷复现用例**故意写成「期望失败」**（`pytest.mark.xfail`）——
当前系统确实存在这些问题，它们「失败」才说明缺陷被真实抓到。

细节见 [docs/缺陷报告.md](docs/缺陷报告.md)。

## 7. 用到的测试方法

- **边界值分析**：免费时长恰好 15 分钟 / 15 分 1 秒、恰好 1 / 2 / 3 小时、
  24 小时封顶、车位恰好停满、61 分钟这个「零头」边界
- **等价类划分**：车牌格式（缺省份简称 / 第二位非字母 / 位数不足 / 位数过多）、
  日期格式（斜杠 / 月份 13 / 中文 / 空）
- **状态迁移测试**：车辆在「在场 → 出场」之间的迁移，以及重复出场这一非法迁移
- **边界条件测试（容量）**：7 个车位停满后拒绝入场；充电位仅 1 个
- **并发测试**：`threading.Barrier` 让 12 辆车对齐后同时请求入场
- **幂等性测试**：重复调用出场接口，断言副作用不叠加

## 8. 技术要点

- **时间可控**：`service.advance_clock(seconds)` 把系统时钟整体前移，
  让「停车 150 分钟」这类用例在毫秒内完成，且不依赖真实等待
- 被测系统只用 Python 标准库，**clone 下来不用装任何东西就能跑**
- 每个用例前自动重置内存数据与时钟，用例之间零污染
- 断言直接比对**车位总览的真实数字**，而不是只看接口返回值

## 9. 已知局限

- 内存存储，无持久化；服务重启后数据重置（不影响测试结论）
- `service.DB_ROUND_TRIP` 是对数据库往返延迟的**模拟**，用于让并发缺陷可稳定复现
- BUG-S3 的「成功入场车辆数」每次运行略有浮动（受线程调度影响），
  但**每次都被分配到同一个车位**这一点是稳定复现的
- 未覆盖：地磁/道闸等硬件对接、支付通道、性能压测
