# 智能停车管理系统 smart-parking

一个完整的停车场管理系统，用作**软件测试练习靶场**：能真实地分配车位、计费、结算出口，
也能真实地把一个车位同时发给 20 辆车、把别人还停着的车位释放掉、让过期月卡永远免费。

- 前端：原生 HTML + CSS + JavaScript（车场车位网格图 + 页面交互，无需 npm 构建）
- 后端：Python Flask（页面路由 + JSON 接口）
- 数据库：MySQL / MariaDB（4 张表，真实外键）
- 测试：pytest（102 条用例：89 通过 + 13 预期失败，对应 4 个刻意埋入的缺陷）

---

## 一、快速开始

### 1. 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Python | 3.9+ | 建议 3.11 以上 |
| MySQL / MariaDB | 5.7+ / 10.4+ | 本项目在 MariaDB 10.4.14 上验证通过 |
| 浏览器 | 任意现代浏览器 | Chrome / Edge 均可 |

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

### 3. 配置数据库连接

数据库地址、账号密码都在 `config.py` 里，默认值：

```
host = 127.0.0.1    port = 3306
user = root         password = 123456
database = smart_parking
```

如果你的 MySQL 密码不是 `123456`，改 `config.py`，或者设环境变量 `SMARTPARK_DB_PASSWORD`。

### 4. 初始化数据库

```bash
python init_db.py
```

创建 `smart_parking` 库、4 张表，写入 7 个车位和 2 张月卡。
（这点数据是**刻意压小的**，为了让并发缺陷和边界用例稳定复现；
想看成规模的运营数据，见第三节末尾的「演示数据」。）

### 5. 启动服务

```bash
python app.py
```

浏览器打开 **http://127.0.0.1:5002/** 即可看到车场总览。

## 二、页面功能

| 页面 | 地址 | 功能 |
| --- | --- | --- |
| 车场总览 | `/` | 车位统计、车位网格图、按类型统计、数据一致性自检 |
| 入场登记 | `/entry` | 输入车牌分配车位、查看在场车辆 |
| 出场结算 | `/exit` | 结算费用、显示计费明细、释放车位 |
| 停车记录 | `/tickets` | 全部记录，按车牌/状态筛选，显示时长与费用 |
| 月卡管理 | `/card` | 办理/续办月卡，标记有效期状态 |

> **页面上有个「测试时钟」**：计费要靠停车时长，总不能真等 3 小时。
> 点「+1 小时」把时钟前移，再点「出场结算」就能看到按 1 小时计费。
> 这是**测试专用**的便利功能（对应接口 `POST /api/dev/clock`）。

## 三、初始数据

**车位（共 7 个，刻意压得很小）**

| 编号 | 类型 | 说明 |
| --- | --- | --- |
| A-001 ~ A-004 | NORMAL | 普通车位 |
| B-001 ~ B-002 | ACCESSIBLE | 无障碍车位 |
| C-001 | CHARGING | 充电车位（**只有 1 个**） |

**月卡**

| 车牌 | 有效期至 | 状态 |
| --- | --- | --- |
| 京A12345 | 2027-12-31 | 有效 |
| 京B00001 | 2024-01-01 | **已过期**（用于验证 BUG-S4） |

**车牌格式**：首位省份简称 + 字母 + 5~6 位字母数字，例如 `京A12345`、`粤B8888E`。

### 演示数据（让系统看起来像真在跑）

上面那 7 个车位是测试基线，页面会显得很空。
`demo_data.py` 在这之上灌入「几个月真实运营」量级的数据，**不破坏缺陷复现**：

```bash
python demo_data.py          # 灌演示数据（会先重置为基线，可重复执行）
python demo_data.py clear    # 清空演示数据，回到 seed.sql 的干净基线
```

灌完后大致规模：

| 对象 | 基线 | 灌入后 | 说明 |
| --- | --- | --- | --- |
| 车位 | 7 | 80 | A/B/C 三区，含 5 个无障碍位、8 个充电位 |
| 月卡 | 2 | 24 | 其中 5 张已过期 |
| 停车记录 | 0 | 320 | 270 条已出场 + 50 条正在场内 |
| 车位流水 | 0 | 590 | 每一次 ENTRY / EXIT 都有流水 |

数据用固定随机种子生成，**每次灌出来的都一样**，方便截图、录屏、做前后对比。
同时保证三条不变量成立（见第六节「数据一致性自检」），所以灌完照样能跑缺陷复现脚本。

## 六、如何做测试（三条主线）

### 1. 黑盒手工测试

按 `docs/04-测试用例.md` 逐条执行，用 Excel 记录实际结果。
接口层用 **Postman / Apifox**：导入 `docs/02-接口文档.md` 里的接口。
抓包用 **Fiddler**；查数据用 **Navicat**（连 `127.0.0.1:3306` / root / 123456 / `smart_parking`）。

重置数据（不用重启服务）：

```bash
python init_db.py reset
# 或接口：POST http://127.0.0.1:5002/api/dev/reset
```

### 2. 自动化测试

```bash
pytest                       # 全量
pytest tests/bugs/ -v        # 只看缺陷回归
pytest --cov=. --cov-report=html
```

测试套件会自己起一个测试服务（127.0.0.1:5012），每条用例前自动重置数据 + 时钟，
**不需要先手工启动 `app.py`**。

### 3. 缺陷验证与数据一致性

```bash
python tools/verify_bugs.py   # 一键复现 4 个缺陷，打印期望 vs 实际
```

页面上还有「**数据一致性自检**」按钮，校验三条不变量：

1. 占用车位数 == 在场记录数
2. 每个占用车位都有对应的在场记录
3. 每个车位的「ENTRY 条数 − EXIT 条数」= 1（占用）/ 0（空闲）

任何一条不成立，都说明出现了并发或状态机缺陷。（对应接口 `GET /api/consistency`）

## 七、已知缺陷清单（练习用）

| 编号 | 模块 | 严重度 | 一句话描述 |
| --- | --- | --- | --- |
| BUG-S1 | 计费 | 中 | 计费向下取整，不足 1 小时的零头被抹掉，少收钱 |
| BUG-S2 | 出场 | 高 | 出场不幂等，重复出场会释放**别人**的车位 |
| BUG-S3 | 入场 | 严重 | 并发入场时「查车位」与「占车位」非原子，一个车位发给多辆车 |
| BUG-S4 | 月卡 | 高 | 过期月卡仍然免费，车场持续漏收 |

详细复现步骤、期望结果、实际结果、修复建议见 `docs/05-缺陷报告.md`。

## 八、换端口 / 换数据库

```bash
python app.py 8080                      # 换服务端口
SMARTPARK_DB_PASSWORD=xxx python app.py # 换数据库密码
SMARTPARK_DB_LATENCY=0 pytest tests/bugs/test_bug_concurrent_entry.py
                                        # 关掉人为延迟，观察竞态窗口消失
```

`config.py` 里的 `SIMULATE_DB_LATENCY` 是给并发缺陷用的：
真实系统里「查车位」和「占车位」之间必然有一次网络往返，正是这段间隙让超卖成立。
本机数据库同机访问太快，窗口小到偶现，所以把延迟显式化，让缺陷**稳定复现**。
